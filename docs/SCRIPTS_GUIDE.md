Это руководство описывает, как Vox Bee запускает пользовательские скрипты сейчас, какие есть ограничения безопасности и как писать примеры, которые реально будут работать.

Оно относится только к пользовательским скриптам, добавленным через менеджер скриптов. Внутренние Python-модули самого проекта это руководство не описывает.

## ⚠️ Что важно понять сразу

- Руководство ниже относится к скриптам, добавленным через `Трей -> Скрипты -> Управление скриптами`.
- Vox Bee запускает только поддерживаемые типы файлов: `.py`, `.bat`, `.cmd`, `.ps1`, `.exe`, `.sh`.
- Запуск разрешён только из доверенных папок:
  - встроенная папка проекта `scripts/`
  - пользовательская папка данных `scripts/`, которую создаёт приложение
- Если вы добавляете внешний файл из другой папки через менеджер скриптов, Vox Bee сначала копирует его в доверенную папку `scripts/`, а уже потом сохраняет и запускает.
- Неподдерживаемые типы файлов больше не открываются через систему.
- PowerShell-скрипты запускаются без `ExecutionPolicy Bypass`.

Важно: после добавления внешнего файла Vox Bee запускает не исходный файл из произвольной папки, а его сохранённую копию в доверенной `scripts/`.

## ▶️ Как Vox Bee запускает скрипты

Фактическое поведение в коде:

| Параметр | Как работает |
|---|---|
| Интерпретатор `.py` | тот же Python, которым запущен Vox Bee |
| Рабочая папка | папка самого скрипта |
| Консольное окно | не создаётся |
| Вывод | `stdout` и `stderr` пишутся в лог Vox Bee |
| Кодировка вывода | Vox Bee читает вывод как UTF-8 |
| Таймаут ожидания | 30 секунд |
| После таймаута | Vox Bee перестаёт ждать, но сам дочерний процесс может продолжить работу |
| Блокировка распознавания | нет, запуск уходит в отдельный поток |

Точные команды запуска:

| Формат | Команда |
|---|---|
| `.py` | `python script.py` или `VoxBee.exe --run-script script.py` в собранной версии |
| `.bat` | `cmd /c script.bat` |
| `.cmd` | `cmd /c script.cmd` |
| `.ps1` | `powershell -NoProfile -NonInteractive -File script.ps1` |
| `.exe` | прямой запуск файла |
| `.sh` | `bash script.sh` |

Неподдерживаемые расширения возвращают ошибку и не запускаются через файловые ассоциации.

## 🛡️ Гарантии и ограничения

Vox Bee гарантирует только следующий контракт запуска:

- запускает поддерживаемый скрипт разрешённым способом;
- пишет `stdout` и `stderr` в лог Vox Bee;
- ждёт завершения до 30 секунд;
- не блокирует распознавание на время запуска.

При этом важно понимать ограничения:

- после таймаута Vox Bee перестаёт ждать, но дочерний процесс может продолжить работу;
- Vox Bee не превращает интерактивный скрипт в нормальный UI-сценарий;
- Vox Bee не обходит системные ограничения PowerShell;
- Vox Bee не резолвит произвольные типы файлов через Windows Shell.

## 🔒 Доверенные папки и безопасность

Сейчас это одна из самых важных частей поведения.

- Скрипт нельзя запустить напрямую из произвольной папки.
- Если путь уже находится внутри доверенной папки, он сохраняется как есть.
- Если вы выбрали внешний файл через менеджер скриптов, Vox Bee копирует его в пользовательскую `scripts/`.
- Если в доверенной папке уже есть файл с таким именем, создаётся имя с суффиксом: например `tool_1.py`.
- Если файл не существует, менеджер покажет ошибку ещё на этапе сохранения.

Практический вывод:

- если хотите стабильное поведение, храните рабочие скрипты в `scripts/`;
- если редактируете внешний файл и ожидаете, что Vox Bee будет запускать именно его, это неверно: после добавления используется копия в доверенной папке;
- после изменения внешнего оригинала его нужно заново добавить или вручную обновить копию в `scripts/`.

## 📖 О чём это руководство

Это руководство описывает скрипты, добавленные через менеджер скриптов в трее.

## 🐍 Рекомендуемый шаблон Python-скрипта

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""
Краткое описание: что делает скрипт.
"""

import io
import sys

if sys.platform == "win32":
    sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding="utf-8", errors="replace")
    sys.stderr = io.TextIOWrapper(sys.stderr.buffer, encoding="utf-8", errors="replace")


def main():
    print("[MY_SCRIPT] Старт")

    try:
        # Ваш код
        print("[MY_SCRIPT] Готово")
        return 0
    except Exception as e:
        print(f"[MY_SCRIPT] ОШИБКА: {e}")
        return 1


if __name__ == "__main__":
    sys.exit(main())
```

## ✍️ Что писать в Python-скриптах

Рекомендуемый минимум:

- UTF-8-обёртка для `stdout/stderr` на Windows;
- `main()` с явным `return 0/1`;
- `if __name__ == "__main__": sys.exit(main())`;
- понятные `print()` с префиксом вроде `[OPEN_APP]` или `[BACKUP]`;
- явная обработка ошибок.

Почему это важно:

- лог Vox Bee будет читаемым;
- код возврата попадёт в лог;
- скрипт будет одинаково вести себя и при ручном запуске, и из Vox Bee.

## 🚫 Чего лучше не делать

- Не используйте `input()`: у скрипта нет интерактивной консоли.
- Не проектируйте интеграцию как интерактивный консольный сценарий: `input()` и ожидание ввода здесь считаются неправильной моделью.
- Не полагайтесь на текущую рабочую папку как на папку Vox Bee.
- Не рассчитывайте, что любой файл откроется по расширению через Windows.
- Не рассчитывайте на обход PowerShell policy через `Bypass`: если `.ps1` блокируется системой, это не ошибка Vox Bee.
- Не делайте долгую синхронную работу, если её можно вынести в отдельный процесс через `subprocess.Popen()` или другой неблокирующий запуск.

## 📁 Пути и файлы

Скрипт стартует с `cwd`, равным папке самого файла. Лучше всё равно писать пути явно:

```python
from pathlib import Path

SCRIPT_DIR = Path(__file__).resolve().parent
CONFIG_PATH = SCRIPT_DIR / "config.json"
```

## 📦 Зависимости

Python-скрипты используют то же окружение Python, что и Vox Bee.

Это значит:

- стандартная библиотека Python доступна;
- сторонние пакеты должны быть реально установлены именно в том Python-окружении, где работает Vox Bee;
- если пример требует `pywin32`, это нужно явно учитывать.

Если зависимость не установлена, лучше завершаться понятной ошибкой:

```python
try:
    import win32gui
except ImportError:
    print("[MY_SCRIPT] ОШИБКА: требуется pywin32")
    sys.exit(1)
```

## 🧪 Примеры из папки `scripts/`

В репозитории сейчас есть такие примеры:

- `scripts/open_notepad.py`
  - рабочий минимальный пример запуска `notepad.exe`;
  - хороший стартовый шаблон.
- `scripts/open_app.py`
  - пример словаря приложений;
  - подходит как база для своих приложений;
  - исправлен для шаблонных путей вроде `app-*`.
- `scripts/create_folder.py`
  - пример работы с Explorer через `pywin32`;
  - требует Windows и установленный `pywin32`;
  - приведён к нормальному `return`/`sys.exit`.
- `scripts/close_window.py`
  - пример автоматизации окна под курсором;
  - тоже завязан на Windows и `pywin32`;
  - описание поправлено, чтобы не вводило в заблуждение.
- `scripts/test_echo.bat`
  - минимальный `.bat`-пример;
  - теперь сразу переключает консоль на UTF-8 через `chcp 65001`.

## 📄 Пример `.bat`

```bat
@echo off
chcp 65001 >nul
echo [TEST] Скрипт запущен
mkdir "%~dp0output" 2>nul
echo done > "%~dp0output\result.txt"
exit /b 0
```

## 📄 Пример `.ps1`

```powershell
$OutputEncoding = [Console]::OutputEncoding = [System.Text.UTF8Encoding]::new()
Write-Output "[TEST] PowerShell script started"
exit 0
```

Важно:

- PowerShell запускается как `-NoProfile -NonInteractive -File`;
- если политика исполнения в системе запрещает запуск `.ps1`, Vox Bee её не обходит.

## 🐞 Как отлаживать

1. Сначала запускайте скрипт вручную.

```text
cd C:\path\to\script
python my_script.py
```

2. Потом добавляйте его через менеджер скриптов.

3. Включайте логирование в трее и смотрите строки вида:

```text
[SCRIPTS] 🚀 Запуск: my_script.py
[SCRIPTS]    Команда: ...
[SCRIPTS]    Рабочая папка: ...
[SCRIPTS]    📤 ...
[SCRIPTS]    ⚠️ ...
[SCRIPTS] ✅ Завершён: my_script.py (код: 0)
```

4. Если файл был добавлен извне, проверяйте именно копию в доверенной папке, а не исходный оригинал.

Нормальный порядок отладки такой:

- ручной запуск;
- запуск через Vox Bee;
- проверка лога Vox Bee;
- проверка именно доверенной копии в `scripts/`, если исходный файл добавлялся извне.

## 🚑 Частые проблемы

| Проблема | Причина | Что делать |
|---|---|---|
| `Файл не найден` | путь неверный или файл удалён | проверить сохранённый путь в менеджере |
| `Запуск вне доверенных папок запрещён` | файл лежит вне доверенных директорий | добавить через менеджер, чтобы файл был скопирован в `scripts/` |
| `Неподдерживаемый тип скрипта` | расширение не входит в разрешённый список | использовать `.py`, `.bat`, `.cmd`, `.ps1`, `.exe` или `.sh` |
| `UnicodeEncodeError` или кракозябры | скрипт пишет не в UTF-8 | добавить UTF-8-обёртку |
| `ModuleNotFoundError` | зависимости нет в окружении Vox Bee | установить пакет в это окружение или переписать скрипт |
| после изменения внешнего файла ничего не меняется | Vox Bee запускает копию из доверенной папки | обновить файл внутри `scripts/` или добавить заново |
| `.ps1` не стартует | политика PowerShell запрещает запуск | подписать скрипт, изменить системную policy или использовать другой формат |
| скрипт "висит" | используется `input()` или долгий блокирующий вызов | убрать интерактивность, для долгих процессов использовать `Popen()` |

## ✅ Чек-лист перед добавлением

- файл лежит в доверенной папке или будет скопирован туда через менеджер;
- расширение поддерживается;
- Python-скрипт сохранён в UTF-8;
- `stdout/stderr` обёрнуты в UTF-8 на Windows;
- есть `main()` и `sys.exit(main())`;
- ошибки логируются понятно;
- нет `input()` и другого ожидания консольного ввода;
- долгие процессы запускаются неблокирующе, если это нужно;
- скрипт проверен вручную до добавления в Vox Bee.
